# Sajag security review

Reviewed the local source at baseline `e26ac4e`, the team’s My Reports integration at `b9dc920`, and the fixes on `devangingale/sajag-security`. The [companion database review](security/claude-db-review.md) informed the migration. The review covered the public API, Vite middleware, database migrations and Auth boundaries, client rendering and URLs, service worker, build output, and production dependencies. Findings describe reachable effects and their prerequisites from source. The hosted application, database, and account settings were outside the review. No migration was executed.

## Database and Realtime

- The original migration enables RLS on both tables. Reports can be inserted only under the caller’s UUID and deleted only by their owner. There is no report update policy. A voter cannot set another account’s UUID, update another account’s vote, or delete votes directly. The composite primary key limits each identity to one vote per report. A voter can change their own vote. The anonymous API role can read, and anonymous Auth identities are a distinct case. [Original migration](../supabase/migrations/20261121084811_reports_and_votes.sql#L29) · [Supabase anonymous Auth](https://supabase.com/docs/guides/auth/auth-anonymous)
- The shared schema has no `source`, `tier`, `status`, or confirmation columns for clients to set. The row converter always sets citizen source and derives counts from votes. The separate corroboration weakness can still produce a confirmed status from one reporter. Pasted posts stay client-local and carry an unverified source. [Report conversion](../src/backend/reports.js#L10) · [Lifecycle](../src/engine/lifecycle.js#L12) · [Paste flow](../src/ui/paste.js#L76)
- The draft migration keeps public reads and uses restrictive RLS policies alongside the ownership policies. It derives report identity from the signed-in request, records server time, and stores successful submissions in a private quota table. The quota UPSERT serializes submissions for a single account and rolls back with failed inserts. The quota starts empty at migration time. The new vote guard applies to new writes. Review legacy self-votes, photos, amenities, and suspicious historical timestamps separately before validating constraints or repairing data. [Draft migration](../supabase/migrations/20261121134445_harden_citizen_report_writes.sql) · [PostgreSQL Read Committed semantics](https://www.postgresql.org/docs/18/transaction-iso.html)
- Before enabling anonymous sign-in, review existing data, confirm request JWTs carry the expected `is_anonymous` claim, and verify CAPTCHA and signup throttling. Keep the OAuth redirect allowlist scoped to known app and development origins. The proposed policy leaves anonymous cooling submissions available, so throwaway accounts can still spam cooling points. [Supabase anonymous Auth guidance](https://supabase.com/docs/guides/auth/auth-anonymous)
- Supabase documents that Postgres Changes DELETE events have filtering and RLS limitations. The migration removes raw vote events because their primary key contains a voter UUID. The replacement publishes only the report UUID, city and change time. Publish the compatible client before applying the migration so current clients can use the RPCs and receive vote updates. The client falls back to the legacy tables when the RPC is absent and keeps independent Realtime subscriptions for the rollout. Reload older browser sessions once the migration is in place. [Supabase Realtime behavior](https://supabase.com/kb/troubleshooting/realtime-messages-not-arriving)

### Verify after applying in a disposable database

Use a disposable Supabase instance with PostgreSQL 15 or later for the publication column list. The checked-in local Supabase config specifies PostgreSQL 17. After applying the migration there, these read-only catalog checks should show both account-column permissions as false and show the two public publication entries with no `user_id` in either column list.

```sql
select
  has_column_privilege('anon', 'public.reports', 'user_id', 'SELECT') as anon_report_owner,
  has_column_privilege('authenticated', 'public.report_votes', 'user_id', 'SELECT') as signed_in_voter_id;

select tablename, attnames
from pg_publication_tables
where pubname = 'supabase_realtime'
  and schemaname = 'public'
  and tablename in ('reports', 'report_votes', 'report_vote_activity')
order by tablename;
```

With disposable accounts, confirm anonymous cooling and public reads still work, anonymous flood writes and voting fail, a permanent user can write a flood report and delete only their own report, and a different permanent user can cast or change one vote. Confirm self-vote rejection, server timestamps, both My Reports RPCs and helper counts, a 200 KB photo limit, city-scoped Realtime vote activity, and that the sixth report fails after five successful submissions even if reports were deleted or submissions overlap. Run database advisors against the disposable instance.

## Transcription spend controls

Use a Vercel WAF fixed-window rate limit for `POST /api/transcribe`, starting at 20 requests per minute per source IP with 429 on excess. Test the threshold with shared venue Wi-Fi. Vercel documents rate limiting on all plans and provides the forwarded IP header used for the process-local backstop. A distributed client can still send requests, and non-browser clients can supply allowed origin headers. Monitor Deepgram credit and preserve the existing manual Help path. [Vercel rate limiting](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting) · [Vercel request headers](https://vercel.com/docs/headers/request-headers)

The browser stops recording after 12 seconds. The 256 KB cap does not establish playback duration for compressed clips, and an upstream timeout does not establish billing duration. Deepgram’s pre-recorded endpoint documents returned duration metadata. Enforce a 15-second decoded audio limit before the provider call once WebM/Opus, Ogg/Opus, and Safari MP4 fixtures can validate a server-side media decoder. Reject clips whose duration cannot be bounded. Keep decoder CPU, memory and runtime bounded too. The tighter byte cap suits typical browser voice clips but high-bitrate recordings may exceed it. [Browser recorder](../src/ui/voice.js#L10) · [Deepgram pre-recorded endpoint](https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded) · [Deepgram response metadata](https://developers.deepgram.com/docs/pre-recorded-audio)

## Candidate app-shell CSP

The checked-in `Content-Security-Policy-Report-Only` header covers `/` and `/index.html` using the project host from the handoff. The value below shows a placeholder for portability. The separate RSS sandbox is enforced. Promote the shell policy to enforcement after the remaining integration checks. [Vercel header configuration](https://vercel.com/docs/project-configuration/vercel-json#headers)

```text
default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: blob: https://protomaps.github.io https://tilecache.rainviewer.com; media-src 'self' blob:; worker-src 'self' blob:; child-src 'self' blob:; connect-src 'self' https://your-project-ref.supabase.co wss://your-project-ref.supabase.co https://protomaps.github.io https://api.open-meteo.com https://api.rainviewer.com https://tilecache.rainviewer.com https://router.project-osrm.org; manifest-src 'self'; object-src 'none'; base-uri 'none'; frame-src 'none'; frame-ancestors 'none'; form-action 'self'
```

- Allow inline styles for existing templates and MapLibre positioning. Keep script sources self-only. In production, `'self'` covers PMTiles, the service worker, and both browser API calls. Deepgram and NDMA are server-side fetches, and Google OAuth uses a top-level navigation. If a deployment uses external PMTiles, a different OSRM instance, or a custom Supabase hostname, add only the configured origins to the corresponding directives. Check the radar tile host in the feed. [MapLibre CSP notes](https://maplibre.org/maplibre-gl-js/docs/) · [Tile and routing configuration](../config.js#L21) · [Radar feed](../src/feeds/rainviewer.js#L17)
- Orca loaded the production build under the candidate enforcing policy on localhost with a mock SACHET feed and Supabase disabled. MapLibre rendered PMTiles features, range requests returned 206, Protomaps and Google Fonts loaded, the service worker controlled the page, both scenarios opened, public OSRM returned a Safe route, and Open-Meteo and RainViewer were reachable. Before enforcing on the hosted app, verify offline reload, route detours, Google/email auth, report and vote updates over Realtime, microphone transcription, and Safari/iOS.

## Verification and boundaries

- Reviewed every `innerHTML` caller under `src/` and the map-popup path. Report names, gazetteer labels, SACHET text, voice transcripts, and account metadata render via escaping or `textContent`. Static translation and city-pack strings remain trusted bundle inputs. Pasted content is handled through form values and inserted with `textContent`. The alert link is HTTPS and restricted to SACHET. The flood call links strip nondigits, and heat uses only 108 and 112. Both WhatsApp `window.open` calls use a fixed HTTPS host, encoded text, and `noopener`. No application-owned `postMessage` receiver was found.
- Ran all four repository self-test scripts and `npx vite build` before each commit. Local mock checks exercised transcription request limits and errors, SACHET state validation and response headers, the service worker cache allowlist and offline fallback, and the My Reports and voting clients against mocked RPC and legacy paths. Build output retained the existing size warning for the main JS chunk.
- Scanned the actual `dist/` client text assets for private key-like strings, reporting filenames only on matches. No private credential pattern matched. This worktree had no `.env.local`. A separate build with synthetic environment markers included the Supabase URL and publishable key and excluded the Deepgram, Gemini, and Supabase service-role markers. The currently hosted bundle and provider settings were outside verification.
- `npm audit --omit=dev` reported one Critical advisory on MapLibre GL JS and zero other production dependency findings. The audit is report-only. Its exit status was 1 because of that advisory.
